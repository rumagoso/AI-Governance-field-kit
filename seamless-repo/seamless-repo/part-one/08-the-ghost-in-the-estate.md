# The Ghost in the Estate

*A developer's personal login to an unreviewed browser extension became the way attackers reached a major platform, not because any control failed, but because the tool had never been counted in the first place.*

The Vercel breach of April 2026 did not begin with a zero-day exploit or a misconfigured cloud bucket. It began when a developer, working on personal productivity, signed into a browser extension called Context.ai using their corporate Google Workspace credentials. No contract existed between the two companies. No security review had taken place. The tool was not part of any enterprise deployment; a single employee had simply tried it. Weeks later, an unrelated breach at Context.ai harvested that employee's credentials and session tokens, and the attackers walked straight into Vercel's systems through a door that, as far as Vercel's own security programme was concerned, did not exist.

It is tempting to read this as an access-control failure, or a vendor-risk failure, or a training failure. It was none of those, or rather, it was all of them at once, for the same underlying reason: none of Vercel's controls had a chance to fire, because none of them knew there was anything to control. Access review cannot restrict a connection it has never logged. Vendor due diligence cannot assess a vendor nobody told it about. The failure sits one level below all the usual categories. It sits in the inventory, or rather in the absence of one entry that should have been there and wasn't.

## Why inventory comes first

This is not a new insight, which is precisely what makes it worth restating. The CIS Critical Security Controls, the closest thing information security has to an agreed order of operations, list eighteen controls in their current version. Inventory and Control of Enterprise Assets sits first. Inventory and Control of Software Assets sits second. Access control, vulnerability management, data protection, incident response, all of it, comes after. That ordering is not a stylistic choice. Every control from the third onward is conditional on the first two, because every one of them presupposes that the thing being controlled has already been counted. A patching programme cannot patch a system it does not know runs. A monitoring programme cannot flag anomalous behaviour in a tool it has never seen. Governance, in the most literal sense, cannot reach what it cannot see, and inventory is the only control on the list whose entire function is making things visible in the first place.

Applied to AI, the same logic holds with unusual force, because AI tools are unusually easy to acquire without anyone's approval. A browser extension, a login with a corporate email address, and a system exists inside the organisation's data flows that no risk register, no conformity assessment, and no incident-response runbook has ever heard of. IBM's 2026 Cost of a Data Breach Report puts a number on how often this now matters: incidents involving unapproved AI tools jumped to 43% of breaches this year, roughly double the year before, and the organisations affected shared a common trait, not bad controls, but no visibility into what needed controlling.

## A different problem from the one already named

An earlier piece in this collection argued that AI inventories rot, that the evidence an organisation holds about the systems it knows about decays faster than anyone revisits it. That is a real problem, and it assumes something this piece cannot: that the system in question made it into the inventory to begin with. The Vercel incident was not a case of stale evidence about a known system. Context.ai was never entered anywhere. There was no record to go stale, because there was no record. Freshness and coverage fail in different directions, and an organisation can be excellent at one while being blind in the other. A perfectly current inventory of sixty per cent of an AI estate is not sixty per cent as good as a complete one. It is, for practical purposes, no better than no inventory at all, because the incident that finds you will almost certainly come from the forty per cent nobody counted.

## What the ordering is actually saying

CIS did not put inventory first because it is the easiest control to implement. It put it first because it is the only one that makes every subsequent control possible, and because a security programme that skips straight to sophisticated defences while leaving its asset inventory incomplete has built an elaborate set of controls around a building whose side door nobody photographed. Vercel had access controls. It had a security team. What it did not have was a record that Context.ai existed at all, and no amount of sophistication downstream of that gap could have caught what the gap itself had already let through.
